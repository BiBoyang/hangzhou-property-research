# TASK-seller-perspective：卖房者视角的市场分析

## 背景（2026-09-21）

系统当前定位是个人购房工具：61 份文档（53 PDF + 8 网页采集）、1632 个 chunk、
1517 条指标、25 题验收集 25/25。判断下行周期内，卖房者侧的分析需求可能大于
买房者侧，故立项评估"从卖房者角度做市场行情分析"。

关键前提：双层架构（文档层 + 指标层）不带立场，`market_phase` 输出的是规则对
证据的整理，刻意不给购房建议。卖方视角不需要新 RAG、不需要改索引结构，需要的
是：卖方问题集、现在库里缺失的流动性指标、以及一层"同一份证据、相反读法"的
解读。

### 卖房者不是一类人（问题集分组依据）

- **置换者**：卖一买一，同时是买方。核心问题是"卖出标的与买入标的的价差在
  扩大还是收窄"，现有多来源时间序列（3A）与城市横向比较（3C）可复用。
- **投资离场者**：核心问题是"现在走还是再等等"，需要持有/等待成本账。
- **急售者**：核心问题只有一个——"挂多少钱能在 N 个月内成交"，依赖成交
  周期、议价空间等微观流动性数据。

## 分阶段范围（严格按顺序，后一阶段以前一阶段产出为门槛）

### Phase 1：卖方问题集 + 现有语料盲跑（下一个 feature，可立即开工）

沿用 25 题验收集的老打法：先写问题、不补数据、盲跑出缺口清单。

- 写 15–25 道卖方问题，按三种角色分组；问题应覆盖：数据定位（我这类房子
  现在能卖多少/多久卖掉）、时点与成本（现在卖还是等）、跨城/跨标的比较
  （置换价差）、边界拒答（库里没有的微观数据能不能老实说没有）。
- 用现有 61 份语料与 1517 条指标盲跑：每题走现有 `search()` + 指标查询，
  记录命中/未覆盖/仅部分覆盖，产出覆盖缺口报告（按角色 × 问题类型汇总）。
- 预计数据定位类大面积"未覆盖"——该失败即 Phase 2 的补数据清单：哪些
  指标能从研报抽、哪些必须换来源（如贝壳研究院月报）。
- 不写解读层，不改 schema，不引入新数据源。

**修改文件**：

- `eval/seller_questions.yaml`（新增）：卖方问题集，格式参照
  `eval/questions.yaml`（q / expect，盲跑阶段 expect 可留空）。
- `scripts/run_seller_coverage.py`（新增，只读）：盲跑 + 覆盖缺口报告，
  复用 `lib_search.search` 与 `lib_metrics_query`，不维护第二套检索；
  全程只读，无写入子命令。
- `plans/TASK-seller-perspective.md`：本文件。

**门槛**：缺口报告完成并人工判读后，才决定 Phase 2 排不排、补哪些指标。
即使最终不做卖方视角，本批问题也可作为现有检索的额外回归集，不浪费。

### Phase 2：流动性指标（成本大头，待 Phase 1 拍板）

卖方视角压得最重的指标，恰好是库里最薄的：挂牌量、降价房源占比、带看量、
成交周期、挂牌价与成交价的议价空间。现状：挂牌类指标 schema 缺位（见
SESSION-2026-09-16 遗留问题），`volume_new_home` / `inventory` 信号
insufficient。

- 先验证来源可得性：投行研报只覆盖城市级宏观聚合，微观流动性数据在贝壳、
  链家平台手里；需确认贝壳研究院/克而瑞报告中的相关指标能否喂饱，喂不饱
  的指标接受继续留空，不用 LLM 编造。
- 补指标沿用现有生命线：schema 先行（量价分家的既有教训）、每条指标带
  `source_quote`、程序断言（原文子串 + 数字出现在引文中）、抽样人审。
- 新增数据走 BYOD 管线与 `load_external_metrics.py` 幂等导入，不动
  3A–3E 的"不求平均、不合并、缺失不插值"哲学。

### Phase 3：卖方解读层（依赖 Phase 2，规则型）

下行市场里买方等待成本低、期权在买方手里；卖方等待有明账。新增规则层把
同一份证据做卖方读法，例如：按当前跌幅与去化周期，挂价每多扛一个月的
预期损失区间。

- 风格对齐 `market_phase.py`：透明规则、可追溯证据、规则版本号、显式
  布尔条件、无黑箱评分；输出是证据整理与情景测算，不输出"应该卖/不
  应该卖"的指令。
- 复用 3A–3D 只读接口，不维护第二套 SQL/分组；零外部 API。
- 与现有市场阶段的关系：阶段判断不变，解读层是其下游的另一个读者视角，
  买方/卖方解读共用同一批证据，避免两套事实。

## 验证与防回归

- Phase 1 全程只读：正式库指纹（size/mtime/sha256）前后不变，零写入。
- 任何阶段完工后跑现有 25 题回归：`run_eval.py` 通过数不应低于 22。
- Phase 2/3 新增逻辑配套单测，`.venv/bin/python -m unittest discover -s tests`
  全量绿；新增 Web 入口时沿用 mode=ro、XSS 转义、非法参数 422 的既有契约。
- Phase 3 的输出措辞需过审：只给情景与证据，不出现买卖时点指令。

## 已知边界 / 风险

- 微观流动性数据可能根本无法以研报形式合法获取；若如此，Phase 2/3 不成立，
  系统停在"宏观层卖方问题集 + 诚实的未覆盖"。
- 卖房者个性化极强（小区、楼层、户型、税费），系统能做的是城市/板块级
  条件分析，不替代个案定价。
- 0.6B embedding 的跨语言与长查询短板不变，卖方问题集同样受此约束。

## 对文章的增量（非工程目标，顺带记录）

- "同一个系统、两种立场的读者"：架构中立性可作为设计章节的新论据。
- 买方期权 vs 卖方等待成本，是下行周期里少有的反差点。
- Phase 1 盲跑若复现"大面积未覆盖"，与"25 题验收集/指标会骗人"形成
  同一条方法论：先立靶子再施工，缺口清单本身就是产出。
