# 演示指南（Demo Script）

10 分钟演示路径：3 道问答 + 1 个看板。每道题都对应一个架构决策，边演示边讲。

## 演示前准备（2 分钟）

```bash
cd rag-app
export LLM_API_KEY=你的key    # 或已配置 DEEPSEEK_API_KEY
.venv/bin/python web/app.py   # http://localhost:8666
```

- 启动后等终端打印 `[warmup] 预热完成`（约 30s），先随便问一句热身；
- **断网兜底**：`/overview` 市场总览页全程不依赖 LLM 和外部网络，演示环境网络挂了就直接讲看板部分。

## 第 1 题：观点对比 —— 展示"混合检索 + 多来源生成"

**问**：`高盛、大摩、瑞银对中国房地产市场的最新判断分别是什么？`

**展示点**：
- 回答按机构分列观点，每条带 `[机构 日期]` 引用——生成层被强制要求标注来源，不同机构观点冲突时并列呈现、不和稀泥；
- 中英混检：中文查询能命中英文研报（查询期同义词扩展：瑞银↔UBS、新政↔easing）；
- 点开下方引用来源，跳到原文 chunk（文档浏览页）。

**对应的坑**（被问就讲）：索引文本最初只有正文没有标题，"瑞银公积金报告"类查询沉底——把"报告标题+章节标题+正文"一起索引才解决。

## 第 2 题：数据查询 —— 展示"双层架构"

**问**：`2026年3月杭州百城价格指数环比涨跌多少？样本均价多少？`

**预期回答要点**：新房 +0.34% / 33,592 元/㎡，二手 −0.58% / 32,377 元/㎡ [中指院 2026-03]。

**展示点**：
- 这是查数据不是查文档——向量检索找"语义相近的段落"，但"33592"躺在表格某一行里，语义相似度极低。所以架构拆两层：语义问题走文档层，数据问题走指标层（LLM 抽取 + quote 必须是原文子串的程序断言 + source_file 幂等导入）；
- 回答会主动区分新房/二手两个口径，并指出指标库里的口径冲突——**多来源不求平均、不选"真实值"，冲突并列**是指标层的核心设计；
- 顺势切到 `http://localhost:8666/metrics` 指标看板：同指标多机构分系列展示。

## 第 3 题：边界 —— 展示"不知道就说不知道"

**问**：`高盛对长鑫存储的目标价是多少？`

**预期**：明确回答"现有研报未覆盖"，不编造数字。

**展示点**：
- 听起来很像库里该有的问题（高盛+目标价），但语料全是房地产研报——system prompt 明确禁止编造、数字必须原文照抄；
- 25 题验收集里有 5 道这种边界题，回归保证"拒答能力"不退化。

## 收尾：市场总览 /overview

`http://localhost:8666/overview`（默认杭州）：
- 顶部是市场阶段判断（当前：底部震荡 / 置信度 low）——**规则引擎透明评估，六门条件全部留痕**，不是黑箱打分；
- 价格/成交多来源趋势线：缺失期断线不填 0、同期冲突红点并列、预测虚线单独成线；
- 杭沪深北横向比较：只有严格同口径（同机构/同来源/同粒度）才进主图；
- 强调边界：**系统只整理证据，不输出"该不该买"的结论**——阶段是"规则对证据的整理"，置信度表示证据充分程度而不是判断正确的概率。

## 预判追问速答

| 追问 | 一句话回答 |
|------|-----------|
| 为什么 0.6B embedding？ | 本地 MPS 跑得动、1633 chunk 20 分钟；跨语言短板用同义词扩展+文档先验补，rerank（bge-m3）留作后手 |
| 为什么不用向量数据库？ | 61 份文档 23MB SQLite 全装下：FTS5+sqlite-vec+指标表单文件。对规模的诚实判断比技术栈先进感重要 |
| 幻觉怎么防？ | 三层：生成层强制引用+"未覆盖"话术；指标层 quote 必须是原文子串的程序断言；25 题验收集回归（含 5 道边界题） |
| 数据量 ×100 怎么办？ | 先死的是单机写入和 embedding 吞吐，不是检索——到那时再拆服务，现在的答案是不提前付这个成本 |
| 评测怎么做？ | 25 题五类（数据定位/观点对比/政策/本地/边界），期望词命中判定；三轮检索调优全部由评测失败案例驱动 |
