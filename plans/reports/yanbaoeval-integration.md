# YanbaoEval 重度评测集成报告(2026-10-16)——文章素材底稿

## 集成方式(工程部分)

- YanbaoEval 新增进程内适配器 `src/yanbaoeval/adapters/ragapp.py`(注册进 `_REGISTRY`,不动既有代码):不起 HTTP 服务,直接 `asyncio.to_thread` 调 `lib_agent.run_agent`
- Answer 三件套映射:text=四段式答案;citations=答案中 `[机构 日期]` 引用经 docs 表映射到数据集文档;contexts=全部工具结果原文(喂错题归因)
- rag-app 侧配套:`AgentConfig.capture_contexts`(收集工具结果)、query_claims 工具输出带 doc_id、**末轮强制合成加"必须立即作答"提示**
- YanbaoEval 以 `uv pip install -e` 装进 rag-app 的 venv(反向装需要拖 torch 全家桶)
- 数据集 `datasets/ragapp-mini`:15 篇代表文档(观点/数据/中英/地产+宏观),`yanbaoeval gen`(ds-flash)出 27 题(闭卷过滤自动剔 3 题)+ 手工 3 道 N 类题 = **30 题**

## 重度评测挖出的三个真问题(轻量规则评测全漏掉了)

1. **强制合成轮复读 bug**(已过轻量评测!):检索预算耗尽被迫终答时,模型产出"让我继续搜索。让我再搜索一下。"×N 的退化文本。修复=末轮明确告知"预算用完必须立即作答"。**机制层的 bug 只有端到端评测能撞出来**
2. **topic 过滤的双刃剑**:房地产 agent 对宏观/黄金/EV 题拒答率 44%——这不是 bug 是设计(领域外就该拒),但提醒:数据集跨域时必须用 all 配置评,否则测的是过滤器不是系统
3. **引用粒度不匹配**:我们答案的引用粒度是 `[机构 日期]`,评测要文档级;同一天同机构多份报告(GS 一天 5 篇)导致映射扇出,精确率被结构性稀释。加上语料 228 篇 vs 数据集 15 篇,引到数据集外的引用永远对不上——**引用精确率只在数据集≈语料时有意义**,可核对率才是公平指标

## 错题归因(评测工具最有价值的输出)

所有错题归因均为 retrieval(7-14 题):证据压根没进检索上下文,而非"找到了没答对"。失败模式集中在 Exhibit/表格内嵌数据(如"Exhibit 3 成都人均收入")——chunk 切分对投行 Exhibit 图表的召回是短板。**调优方向明确:检索层(表格/Exhibit 专项),而不是换生成模型**

## 成本

出题 27 题(gen+闭卷过滤)+ 4 轮×30 题评测,合计 ~500 次调用,总成本 **<10 元**(裁判/出题/flash 轮全是 ds-flash,kimi 轮 2×30×4 次调用 ~¥4)。

## 补充问答(2026-10-16 晚,用户视角的三个问题)

**Q: kimi 正确率比 ds 高吧?**
数值上高(74.1% vs 70.4%),但 Δ=3.7pp 折合成题数就是 1 道题(20/27 vs 19/27);n=27 时 Wilson 区间宽 ±17pp,互换一题即翻转。统计上无法区分。真有区分度的是性格:kimi 更敢答(过度拒答 14.8%、自信答错 11.1%),ds 更保守(22.2% / 7.4%)——两种失败偏好,不是强弱。

**Q: 是全量测试吗?**
两轮跑完全相同的 30 题、同为 agent=all 配置,对比公平;但评测集是 228 篇里 15 篇代表文档出的题,结论适用范围是"研报问答任务形态",不是全语料。

**Q: 成本?**(用户账单实数)
ds-flash 一轮 ¥5.62(单题 ~¥0.19),kimi 一轮 ¥12.30(单题 ~¥0.41)。**2.2 倍差价买不来统计上可分辨的正确率差**。机制拆解过的链路里模型智力不是瓶颈(错题 100% 归因检索层)——这是本文核心论点。
边界条件(诚实声明):哪天错题归因从 retrieval 翻成 generation(证据喂进去还答错),才是换贵模型的时机;评测的价值就是标出这个翻转点。

## 扩容集 ragapp-full(2026-10-17 凌晨,128 题 / 68 篇分层抽样文档)

出题管线:分层抽样 68 篇(机构×主题×时间轴,GS 限流 8,保留 mini 15 篇)→ gen 量产 113 题(T 表格 67 / F 事实 46,双闸门剔 8)+ **claims 表程序生成演化题 25 候选→人工二审淘汰 4/5 伪反转**(同 subject 下主题漂移:EV 销量 vs 房企销售算同一"成交量" subject,教训:subject 粒度太粗)→ 5 道真反转 + 手工 N 类 10 道 = **128 题,validate 全过**。

| 指标 | kimi/all(n=118 可答题) | flash/all |
|---|---|---|
| 正确率 | 56.8% [47.8,65.4] | **64.4% [55.4,72.5]** |
| 幻觉率 | 10.2% | 13.6% |
| 诚实拒答率 | 90.0% | 100.0% |
| 漏答率 | 33.1% | 22.0% |
| 引用命中率 | 50.7% | 56.6% |
| 引用精确率 | 38.9% | 27.6%(扇出稀释) |
| 错题归因 | retrieval 43 / generation 8 | retrieval 39 / generation 3 |

**结论修正(比 mini 集更进一步)**:mini 集(n=27)是"统计打平";扩容集(n=118)上 **flash 正确率反超 7.6pp、漏答率低 11pp**,区间仍重叠(未达统计显著),但方向翻转 + 拒答纪律 100% + 归因里 generation 错误更少(3 vs 8)——**"贵引擎买智力余量"的假设在这个系统里两次测量都不成立**。kimi 唯一的强项是引用精确率(38.9% vs 27.6%,它引用更克制/扇出小)。

题型结构注:mini 集正确率(70-74%)高于 full 集(57-64%),因为 full 集表格题(T)占 52% 且短板配额超配——**更难但更真的尺子**。
